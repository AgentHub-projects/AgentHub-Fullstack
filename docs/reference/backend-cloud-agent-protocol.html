AgentHub Protocol

后端与云 Agent 传输格式

本文档描述当前代码中 AgentHub 后端连接下游云 Agent/Orchestrator 的真实协议。当前实现使用 Socket.IO 客户端连接 DOWNSTREAM_ORCHESTRATOR_WS_URL，通过 acp:message 事件传输 JSON-RPC 2.0 风格消息。

来源：downstream-orchestrator.service.ts 来源：shared/src/index.ts 日期：2026-05-28
目录 1. 连接与传输 2. 后端发给云 Agent 3. session/prompt 4. 云 Agent 回传事件 5. 支持类型 6. 当前实现注意事项

1. 连接与传输

连接方向

AgentHub 后端主动连接云端 Orchestrator。一个 AgentHub session 在连接存活时复用一条 Socket.IO 连接。

配置来源

环境变量 DOWNSTREAM_ORCHESTRATOR_WS_URL。未配置时后端走内置 mock Orchestrator。

项目当前值说明
传输库socket.io-client后端作为 Socket.IO client。
URLDOWNSTREAM_ORCHESTRATOR_WS_URL示例：http://downstream.test/acp，命名空间可放在 URL 里。
transportwebsocket代码中设置 transports: ["websocket"]。
自动重连false断线后删除内存连接；下一次 run 重新建立连接。
消息事件名acp:message后端发出的协议消息都通过该 event 发送。
入站事件名session/event、acp:event、acp:message、message这些事件都会进入统一归一化逻辑。

2. 后端发给云 Agent 的消息

所有请求都包在 acp:message 的 JSON-RPC 2.0 envelope 中。当前实现不会等待 JSON-RPC response 来推进状态，而是在发送 prompt 后直接把 run 更新为 running。

2.1 initialize

Socket 连接成功后立即发送，声明 AgentHub 客户端信息和能力。

{
  "jsonrpc": "2.0",
  "id": "init-<agenthubSessionId>",
  "method": "initialize",
  "params": {
    "protocolVersion": "2026-05-agenthub-v1",
    "clientInfo": { "name": "AgentHub", "version": "0.1.0" },
    "capabilities": {
      "sessionResume": true,
      "artifacts": true,
      "fileChangeSnapshot": true
    }
  }
}

2.2 session/load

连接成功后立即发送。当前实现没有单独的 downstream_sessions 表，发送的是 AgentHub session id。

{
  "jsonrpc": "2.0",
  "id": "load-<agenthubSessionId>",
  "method": "session/load",
  "params": {
    "agenthubSessionId": "<agenthub-session-id>",
    "cwd": "/workspace"
  }
}

2.3 session/cancel

用户取消 run 时发送，同时后端把 agent_runs.status 更新为 cancelled 并写入 run.cancelled 事件。

{
  "jsonrpc": "2.0",
  "id": "cancel-<runId>",
  "method": "session/cancel",
  "params": {
    "runId": "<agenthub-run-id>"
  }
}

2.4 session/context

pushContext 方法用于连接已存在时向云 Agent 主动推送完整上下文。它当前不是发送消息主链路的必经步骤。

{
  "jsonrpc": "2.0",
  "id": "context-<agenthubSessionId>-<timestamp>",
  "method": "session/context",
  "params": {
    "type": "init",
    "sessionId": "<agenthub-session-id>",
    "agents": [
      { "agentId": "uuid", "name": "frontend-agent", "description": "...", "provider": 0 }
    ],
    "summaryChain": [
      { "seq": 1, "content": "长期摘要" }
    ],
    "message": "当前消息",
    "recentMessages": [
      { "role": "user", "content": "历史消息" }
    ]
  }
}

3. session/prompt

session/prompt 是后端把用户请求交给云 Agent 的核心消息。参数类型对应 shared 中的 DownstreamPromptInput。

字段类型/取值说明
agenthubSessionIdstringAgentHub 会话 id。
runIdstringAgentHub run id，云 Agent 回传事件必须带它或在 envelope 顶层带 runId。
messageIdstring用户消息 id。
agentIdstring本轮主 Orchestrator 的 Agent 实例 id。
modebootstrap / incremental新连接或断线重连后是 bootstrap；同一连接存活时后续 run 是 incremental。
promptstring用户当前输入文本。
pinsContextSnapshotItem[]始终发送，来自 context snapshot 的 pinned 项。
metadataobject包含 source: "agenthub" 和 contextSnapshotId。
orchestratorSystemPromptstring仅 bootstrap 时发送。
agentsArray<{agentId, description}>仅 bootstrap 时发送，会话中的非 Orchestrator 成员简介。
memory{summary, retrieved}仅 bootstrap 时发送长期摘要和召回记忆。

bootstrap 示例

{
  "jsonrpc": "2.0",
  "id": "prompt-<runId>",
  "method": "session/prompt",
  "params": {
    "agenthubSessionId": "session-1",
    "runId": "run-1",
    "messageId": "message-run-1",
    "agentId": "orchestrator-id",
    "mode": "bootstrap",
    "prompt": "请实现登录页",
    "pins": [
      {
        "id": "pin-1",
        "kind": "message",
        "text": "本轮 pin",
        "tokenCount": 3,
        "importance": 100,
        "pinned": true,
        "createdAt": "2026-05-28T08:00:00.000Z"
      }
    ],
    "metadata": {
      "source": "agenthub",
      "contextSnapshotId": "context-id"
    },
    "orchestratorSystemPrompt": "主协调者提示词",
    "agents": [
      { "agentId": "frontend-agent-id", "description": "前端成员描述" },
      { "agentId": "backend-agent-id", "description": "后端模板描述" }
    ],
    "memory": {
      "summary": "摘要记忆",
      "retrieved": []
    }
  }
}
注意

当前测试明确要求 snapshotJson.recent 和渲染后的 promptText 不直接发给云 Agent；云 Agent 在 bootstrap 中拿到的是 pins、summary、retrieved、system prompt 和 agents。

4. 云 Agent 回传事件

云 Agent 可以通过 session/event JSON-RPC 消息，或通过 acp:event、acp:message、message 事件回传。后端归一化时读取 params、payload 或 envelope 本身。

推荐 envelope

{
  "jsonrpc": "2.0",
  "method": "session/event",
  "params": {
    "runId": "run-1",
    "seq": 2,
    "type": "message.delta",
    "speaker": "frontend-agent-id",
    "payload": {
      "text": "我会先修改登录页 UI。",
      "speaker": "frontend-agent-id"
    }
  }
}
解析字段来源优先级用途
runIdparams.runId，否则 envelope.runId定位当前 run；缺失则丢弃事件。
eventTypeparams.type，否则 params.eventType，否则 envelope.type写入 agent_events.event_type；缺失则丢弃事件。
payloadparams.payload，否则 params事件业务内容。
speakerparams.speaker、payload.speaker、envelope.speaker、默认 orchestrator用于补全说话 Agent。
seqparams.seq写入 agent_events.seq；缺失时后端自动递增。

5. 支持哪些类型

5.1 事件类型

eventType当前后端行为
run.created后端创建 run 时产生，通常不是云 Agent 回传。
run.status后端状态变更事件，如 connecting、running。
message.delta写入 agent_events，按 speaker 在内存 buffer 中累积文本，并实时推送前端。
message.completed把 buffered 文本持久化为 assistant message，关联 run，并写入 context item。
tool.call持久化事件并推送前端；当前没有派生表。
tool.result持久化事件并推送前端；当前没有派生表。
file.change派生写入 file_changes，推送 hub:file_change，并写入 context item。
artifact.upsert创建或更新 artifacts，推送 hub:artifact。
artifact.chunk当前简化为累加文本到 artifact，不使用独立 chunk 表。
artifact.complete把 artifact 标记为 final，推送前端，并写入 context item。
run.completed更新 run 为 completed，写入完成事件，推送 session。
run.failed更新 run 为 failed，写入错误码和错误消息。
run.cancelled取消 run 时写入。
context.updatedpin 或成员变更时写入。

5.2 artifact 类型

kind默认 MIME存储方式
markdowntext/markdown; charset=utf-8通常 inline_text。
texttext/plain; charset=utf-8通常 inline_text。
htmltext/html; charset=utf-8可内联预览。
pdfapplication/pdfbase64 二进制且 OSS 配置存在时存为 oss_object。
docxapplication/vnd.openxmlformats-officedocument.wordprocessingml.document当前前端提供下载/只读入口。
imageimage/png前端可通过内容接口展示。
archiveapplication/zip二进制 artifact。
logtext/plain; charset=utf-8前端以 pre 展示。
otherapplication/octet-stream未知类型会归一化为 other。

5.3 file.change 类型

changeType说明重要字段
added新增文件。path、after.content、patch 可选。
modified修改文件；未知值会归一化为 modified。before.content、after.content、patch。
deleted删除文件。before.content。
renamed重命名文件。oldPath、path。

6. 当前实现注意事项

  • 当前实现没有持久化下游 session 绑定表；连接记录保存在后端内存 connections Map 中。
  • 同一连接存活时，第二次及之后的 session/prompt 使用 mode: "incremental"，只发送 prompt、pins 和 metadata。
  • 断线后下一次 run 会重新连接，重新发送 initialize、session/load，并以 mode: "bootstrap" 发送 prompt。
  • 空闲连接在 1 小时后检查；如果前端仍有该 session 的订阅者，连接会继续保留并延后检查。
  • 未配置 DOWNSTREAM_ORCHESTRATOR_WS_URL 时，后端会走 mock 路径，模拟 message.delta、file.change、artifact.upsert、message.completed、run.completed。
