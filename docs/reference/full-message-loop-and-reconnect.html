AgentHub Runtime Loop

一次真实循环与断线重连过程

本文档按当前代码描述一条消息从前端进入后端、转发云 Agent、再回到前端的完整链路，并说明同一会话中云 Agent 连接断开后下一次 run 如何重新连接和发送 bootstrap 数据。

REST：POST /api/sessions/:id/messages Downstream：session/prompt Realtime：hub:event
目录 1. 总览 2. 前端到后端 3. 后端到云 Agent 4. 云 Agent 到后端 5. 后端到前端 6. 断线后重连

1. 总览

1. 用户输入
前端 composer 调用 sendSessionMessage，发起 POST /api/sessions/:sessionId/messages。
2. 后端落库
后端保存 user message、context item、agent run、session agent 参与关系，并构造 context snapshot。
3. 后端转发
后端连接或复用云 Agent Socket.IO 连接，发送 initialize、session/load 和 session/prompt。
4. 云 Agent 执行
云 Agent 执行任务并回传 message.delta、file.change、artifact.*、run.completed 等事件。
5. 后端派生
后端写入 agent_events，按事件类型派生 messages、file_changes、artifacts、context_items。
6. 前端更新
后端通过 hub:event、hub:artifact、hub:file_change、hub:session 推送浏览器。

2. 前端输入请求到后端

2.1 前端发送请求

前端提交时会清空 composer，并把解析出的 mentioned agent ids 传给后端。如果没有显式 @，当前页面会把 composer 可选成员都作为 mentionedAgentIds 传入。

{
  "content": "@frontend-agent @backend-agent 请实现登录页",
  "mentionedAgentIds": [
    "10000000-0000-4000-8000-000000000002",
    "10000000-0000-4000-8000-000000000003"
  ],
  "orchestratorAgentId": "10000000-0000-4000-8000-000000000001"
}

2.2 后端处理顺序

  1. 校验 content.trim() 非空，并确认 session 存在。
  2. 选择 Orchestrator：优先用请求的 orchestratorAgentId，否则用默认 Orchestrator。
  3. 解析 mentions：合并显式 ids 和文本中的 @agent.name、@agent.id。
  4. 创建 messages 记录，role 为 user，contentJson.mentionedAgentIds 保存被提及成员。
  5. 把用户消息写入 context_items，kind 为 message，importance 为 20。
  6. 创建 agent_runs，初始 status 为 queued。
  7. upsert session_agents：Orchestrator 角色为 orchestrator，被提及成员角色为 member。
  8. 调用 context.buildSnapshot，生成 context_snapshots。
  9. 把 run 的 contextSnapshotId 更新为刚生成的 snapshot id。
  10. 更新 session 标题和 updatedAt。
  11. 通过 WebSocket 推送 hub:session 和 hub:context。
  12. 写入 run.created 事件。
  13. 异步调用 downstream.startRun，HTTP 响应先返回 session、message、run、contextSnapshot。

2.3 HTTP 返回

{
  "session": { "id": "session-1", "title": "@frontend-agent @backend-agent 请实现登录页" },
  "message": { "id": "message-1", "role": "user", "contentText": "@frontend-agent @backend-agent 请实现登录页" },
  "run": { "id": "run-1", "status": "queued", "contextSnapshotId": "snapshot-1" },
  "contextSnapshot": { "id": "snapshot-1", "snapshotJson": { "pins": [], "recent": [], "retrieved": [] } }
}

3. 后端再传给云 Agent

startRun 先把 run 改成 connecting，写入 run.status 事件，再根据 DOWNSTREAM_ORCHESTRATOR_WS_URL 决定走真实云 Agent 还是内置 mock。

3.1 建立连接时的数据

// 连接成功后发送 initialize
{
  "jsonrpc": "2.0",
  "id": "init-session-1",
  "method": "initialize",
  "params": {
    "protocolVersion": "2026-05-agenthub-v1",
    "clientInfo": { "name": "AgentHub", "version": "0.1.0" },
    "capabilities": {
      "sessionResume": true,
      "artifacts": true,
      "fileChangeSnapshot": true
    }
  }
}

// 同一连接建立后发送 session/load
{
  "jsonrpc": "2.0",
  "id": "load-session-1",
  "method": "session/load",
  "params": {
    "agenthubSessionId": "session-1",
    "cwd": "/workspace"
  }
}

3.2 prompt 数据

第一次连接或重连后的 prompt 使用 mode: "bootstrap"，会带 system prompt、成员简介和记忆。

{
  "jsonrpc": "2.0",
  "id": "prompt-run-1",
  "method": "session/prompt",
  "params": {
    "agenthubSessionId": "session-1",
    "runId": "run-1",
    "messageId": "message-1",
    "agentId": "orchestrator-id",
    "mode": "bootstrap",
    "prompt": "@frontend-agent @backend-agent 请实现登录页",
    "pins": [],
    "metadata": {
      "source": "agenthub",
      "contextSnapshotId": "snapshot-1"
    },
    "orchestratorSystemPrompt": "主协调 Agent 的系统提示词",
    "agents": [
      { "agentId": "frontend-agent-id", "description": "前端成员描述" },
      { "agentId": "backend-agent-id", "description": "后端成员描述" }
    ],
    "memory": {
      "summary": "长期摘要文本",
      "retrieved": []
    }
  }
}

发送 prompt 后，后端把连接的 needsBootstrap 置为 false，并把 run 更新为 running，同时推送 session 和 run.status 事件。

4. 云 Agent 再传回后端

云 Agent 回传事件后，后端会执行统一归一化和落库。只要事件没有 runId 或事件类型，就会被忽略。

4.1 文本流

{
  "jsonrpc": "2.0",
  "method": "session/event",
  "params": {
    "runId": "run-1",
    "seq": 2,
    "type": "message.delta",
    "payload": {
      "speaker": "frontend-agent-id",
      "text": "我先实现页面结构。"
    }
  }
}

message.delta 会写入 agent_events 并进入内存消息 buffer，但不会立刻创建最终 assistant message。

4.2 文本完成

{
  "jsonrpc": "2.0",
  "method": "session/event",
  "params": {
    "runId": "run-1",
    "seq": 3,
    "type": "message.completed",
    "payload": {
      "speaker": "frontend-agent-id",
      "text": "登录页页面结构已完成。"
    }
  }
}

message.completed 会把 buffer 或 payload 文本落成 messages(role=assistant)，更新 run 的 assistantMessageId，并写入 context_items。

4.3 文件变更

{
  "jsonrpc": "2.0",
  "method": "session/event",
  "params": {
    "runId": "run-1",
    "seq": 4,
    "type": "file.change",
    "payload": {
      "speaker": "frontend-agent-id",
      "path": "frontend/app/page.tsx",
      "changeType": "modified",
      "language": "tsx",
      "before": { "content": "old", "sha256": "before", "truncated": false },
      "after": { "content": "new", "sha256": "after", "truncated": false },
      "patch": "@@ -1 +1 @@\n-old\n+new\n",
      "stats": { "additions": 1, "deletions": 1 }
    }
  }
}

file.change 会派生 file_changes，推送 hub:file_change，并把 patch 或 after 内容写成 context item。

4.4 artifact 与完成

{
  "jsonrpc": "2.0",
  "method": "session/event",
  "params": {
    "runId": "run-1",
    "seq": 5,
    "type": "artifact.upsert",
    "payload": {
      "artifactKey": "run-summary",
      "kind": "markdown",
      "title": "执行摘要",
      "mimeType": "text/markdown; charset=utf-8",
      "content": "# 执行摘要\n\n已完成。",
      "final": true
    }
  }
}

run.completed 会把 run 更新为 completed，设置 completedAt，再写入一个 run.completed 事件并推送 session。

5. 后端再传回前端

后端动作Socket.IO 事件前端更新
写入任意 HubEventDtohub:event追加/去重到 detail.events，按 seq 排序。
session 更新hub:session更新 session 列表和当前 session 顶部状态。
context snapshot 生成hub:context更新右侧 Context 面板。
artifact upsert/chunk/completehub:artifact更新 artifact 列表，必要时切到 Artifacts tab。
file.change 派生完成hub:file_change更新文件树和 diff 面板，必要时切到 Diff tab。
刷新恢复

前端不是只依赖 WebSocket。刷新页面后会重新调用 GET /api/sessions/:sessionId，从数据库里的 messages、runs、events、artifacts、fileChanges、context 还原页面。

6. 同一会话中断线后重新连接

当前实现没有 Socket.IO 自动重连。云 Agent 连接断开时，后端会清理 idle timer，把 needsBootstrap 设为 true，并从内存连接表删除该 session 的连接记录。

6.1 断线发生时

  1. Socket 触发 disconnect。
  2. 后端清理该连接的空闲检查 timer。
  3. 标记 needsBootstrap = true。
  4. 如果内存 Map 中当前记录仍是这个连接，就删除 connections[sessionId]。

6.2 下一次同 session 发消息时

用户继续在同一个 AgentHub session 发送新消息，后端会创建新的 run 和 context snapshot，然后重新建立下游连接。云 Agent 会收到以下数据：

      "artifacts": true,
      "fileChangeSnapshot": true
    }
  }
}

// 2. session/load
{

  "id": "load-session-1",
  "method": "session/load",
  "params": {
    "agenthubSessionId": "session-1",
    "cwd": "/workspace"

}

// 3. session/prompt，注意 mode 又回到 bootstrap
{

  "id": "prompt-run-2",

  "params": {
    "agenthubSessionId": "session-1",

      ]
    }
  }
}
当前边界

重连过程不是“恢复旧 Socket 上的未完成请求”。当前实现是在下一次 run 需要下游时重新建连，并通过 bootstrap prompt 把必要上下文重新注入给云 Agent。
