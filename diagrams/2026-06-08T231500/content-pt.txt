<h2>设计思路</h2><p>Prompt 构建是 AgentHub 的<strong>核心编排逻辑</strong>。每个 Agent Run 启动时，系统将多种上下文源组装为一个结构化的 Prompt，发送给下游 Agent。设计采用<strong>四层分层结构</strong>：System 层（Agent 身份和规则）→ Context 层（会话上下文快照）→ Agent 层（协作信息）→ Message 层（用户当前请求）。这种分层确保了 Prompt 的可维护性和可调试性。</p><hr/><h2>架构决策</h2><h3>为什么采用四层 Prompt 结构？</h3><p>分层设计使得每层可独立调整和测试：</p><ul><li><b>System 层</b>：定义 Agent 角色和行为边界。包含 Prompt 模式（bootstrap 表示新会话首次运行，incremental 表示后续运行）、可用工具列表</li><li><b>Context 层</b>：来自 ContextSnapshot，是最动态的部分。包含置顶消息（用户手动 Pin）、最近 24 条消息、向量检索结果、结构化会话记忆</li><li><b>Agent 层</b>：当前会话涉及的其他 Agent 信息。在群聊模式下，列出所有被 @ 的 Agent 和可用的 Worker Agent</li><li><b>Message 层</b>：用户的当前输入，包括文本和附件引用</li></ul><h3>为什么区分 bootstrap 和 incremental 模式？</h3><p><b>bootstrap</b>：新会话或断连重连后的首次运行。需要构建完整的 ContextSnapshot（向量检索 + 加载记忆 + 收集置顶），成本较高但确保 Agent 有完整上下文。</p><p><b>incremental</b>：同一会话的后续消息。如果上次运行后 session 保持活跃（Redis key 未过期），可以复用已有的下游连接，跳过快照构建，仅发送新消息。这减少了延迟和 LLM 成本。</p><p>权衡：incremental 模式下 Agent 看不到完整上下文（只有历史对话通过 ACP 协议维护），对于需要跨消息回忆的任务可能不够。但如果 session 活跃超时（1小时），系统会自动回退到 bootstrap。</p><h3>为什么不把完整历史直接放入 Prompt？</h3><p><b>更优方案</b>：直接将所有历史消息序列化放入 Prompt。优势是实现简单，Agent 能看到完整对话。</p><p><b>不采用的原因</b>：</p><ul><li>Token 成本：长会话可能积累数万条消息，全量放入 Prompt 可能超出模型上下文窗口</li><li>信息密度低：大量历史消息中只有少量对当前任务有用，全量传递会稀释关键信息</li><li>通过 ContextSnapshot 的 selectWithinBudget 算法，系统自动选择最重要的上下文（置顶 > 最近 > 语义相关），保证信息密度</li></ul><hr/><h2>Token 预算分配逻辑</h2><p>selectWithinBudget 算法采用<strong>优先级贪婪选择</strong>：</p><ol><li><b>第一轮</b>（优先级最高）：从 pinned=true 的 ContextItem 中选择，预算上限 CONTEXT_TOKEN_BUDGET=9000</li><li><b>第二轮</b>：从最近 24 条消息（反转后按时间正序）中选择，预算上限 CONTEXT_RECENT_TOKEN_BUDGET=4800</li><li><b>第三轮</b>：从向量检索结果中选择，预算为 max(1000, 9000 - 前两轮消耗)。保证至少 1000 tokens 给检索结果</li></ol><p>这个优先级顺序反映了信息重要性：用户手动置顶的内容最重要（显式意图）→ 最近对话（时效性）→ 语义检索（潜在相关）。</p><hr/><h2>与市面平台对比</h2><table><tr><td><p>维度</p></td><td><p>AgentHub</p></td><td><p>OpenAI Assistants</p></td><td><p>LangChain Hub</p></td></tr><tr><td><p>Prompt 构建</p></td><td><p>自动分层+预算</p></td><td><p>黑盒 Thread</p></td><td><p>手动模板</p></td></tr><tr><td><p>上下文选择</p></td><td><p>优先级贪婪</p></td><td><p>不透明</p></td><td><p>开发者控制</p></td></tr><tr><td><p>透明性</p></td><td><p>完全可审计</p></td><td><p>低</p></td><td><p>高但需编码</p></td></tr><tr><td><p>自适应</p></td><td><p>bootstrap/incremental</p></td><td><p>自动管理</p></td><td><p>手动配置</p></td></tr></table><p><b>AgentHub 优势</b>：Prompt 构建过程完全透明——ContextSnapshot 存储在数据库中可审计，renderContextPrompt 生成的文本可直接查看。相比 OpenAI Assistants 的黑盒 Thread 管理，AgentHub 让开发者能确切知道每次发送给 Agent 的 Prompt 内容。</p>
