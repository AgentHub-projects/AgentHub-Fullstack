<h2>设计思路</h2><p>前端采用<strong>类 IDE 布局</strong>：左侧会话列表 + 中央聊天时间线 + 右侧产物检视面板。核心设计理念是<strong>聊天即开发</strong>——用户通过自然语言描述需求，Agent 的回复中内联展示代码 Diff、网页预览等富媒体产物，用户无需切换工具即可完成开发全流程。</p><hr/><h2>架构决策</h2><h3>为什么选择 Next.js 15 App Router？</h3><p>Next.js 15 的 App Router 提供了 Server Components + 流式渲染能力，与 Agent 的流式输出天然匹配。其内置的 rewrite 代理（将 /api/* 和 /socket.io/* 转发到后端 :3001）避免了 CORS 配置和双域名部署的复杂性。</p><h3>为什么组件拆分为 timeline / inspector / composer？</h3><p>三个面板职责清晰且相互独立：</p><ul><li><b>Timeline（时间线）</b>：纯展示，负责消息渲染。通过 EventStreamBuffer 将 Socket.IO 增量事件组装为时间线视图，支持 AgentMessageBubble、ThinkingBlock、TeamPhaseCard 等多种消息卡片</li><li><b>Inspector（检视器）</b>：纯展示，负责产物查看。包含 DiffViewer、ArtifactPanel、FileTree 三个子面板，可全屏展开</li><li><b>Composer（输入框）</b>：纯输入，负责消息构造。支持 @提及 Agent、文件附件、引用回复</li></ul><p>这种拆分使得每个面板可独立开发和测试，状态变更互不干扰。</p><h3>为什么用 @lobehub/ui 组件库？</h3><p>@lobehub/ui 是专为 AI 聊天场景设计的组件库，提供了开箱即用的 Chat 容器、消息气泡、代码高亮等组件。相比从零构建或使用通用 UI 库（Ant Design），它大幅减少了聊天 UI 的开发工作量。</p><hr/><h2>数据流设计</h2><p>前端数据流遵循<strong>单向数据流</strong>模式：</p><ol><li><b>用户输入</b> → Composer 构造消息 JSON → POST /api/sessions/:id/messages</li><li><b>Agent 流式输出</b> → Socket.IO hub:event → EventStreamBuffer.buildEventGroups() → Timeline 增量渲染</li><li><b>产物展示</b> → 点击消息中的产物卡片 → Inspector 加载 Artifact 内容 → 渲染预览</li><li><b>文件上传</b> → Composer 选择文件 → uploadSessionAttachment() → 附件 ID 包含在消息中发送</li></ol><hr/><h2>与市面平台对比</h2><table><tr><td><p>维度</p></td><td><p>AgentHub</p></td><td><p>ChatGPT Canvas</p></td><td><p>Cursor/Copilot</p></td></tr><tr><td><p>交互范式</p></td><td><p>IM 聊天 + 流式</p></td><td><p>编辑器内流式</p></td></tr></table><p><b>AgentHub 优势</b>：独特的 IM 群聊模式让多个 Agent 像群成员一样协作——用户在一个对话中 @不同 Agent，Orchestrator 自动分派任务。相比 ChatGPT Canvas 的单 Agent 限制和 Cursor 的编辑器耦合，AgentHub
